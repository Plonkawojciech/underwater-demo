# Regresja na izolowanej kopii

`pnpm test` uruchamia testy jednostkowe i integracyjne przez oficjalny runner projektu. `pnpm run test:e2e` uruchamia Chromium desktop i mobile przez Playwright. Testy używają nowego trybu headless z `channel: 'chromium'`; wymagają aktualnego buildu oraz pełnego Chromium z `pnpm exec playwright install --with-deps --no-shell chromium`.

Środowisko regresji wymaga Node 22 i Pythona 3.14 z `cryptography==47.0.0` oraz `pypdf==6.12.1`. Biblioteki Python można przygotować poleceniem `python3 -m pip install cryptography==47.0.0 pypdf==6.12.1`. W kontenerze `TMPDIR` musi pozwalać na wykonywanie plików: test startu tworzy tam własny wykonywalny fixture. Zamontowane `/tmp` z `noexec` wymaga osobnego katalogu na wykonywalnym systemie plików, we własnej kopii roboczej.

Playwright automatycznie tworzy własny katalog `underwater-e2e-*`, pustą bazę SQLite i media testowe. Migracje oraz oba seedy dotyczą tylko tego katalogu. Serwer nasłuchuje na loopback:3013; zajęty port jest błędem, a działający podgląd nie jest ponownie używany. Testy sprawdzają przed każdą operacją środowisko `test`, adapter `internal-test` i przechwytywanie poczty. Hasło w fixture dotyczy jednorazowego konta `example.invalid`; nie jest hasłem podglądu ani klienta.

Harness śledzi grupy procesów migracji, seedów i serwera. Przy zamknięciu kończy je przed usunięciem własnej bazy. Nie zatrzymuje procesów innych sesji. Do ręcznej kontroli własnej jednorazowej kopii można ustawić `UNDERWATER_E2E_BASE_URL` razem z `UNDERWATER_E2E_ALLOW_OWNED_COPY=1`; cel musi być HTTP loopback. Ten wariant jest wyłączony w CI.

Workflow `.github/workflows/e2e.yml` uruchamia typecheck, testy, build i E2E. Nie wymaga sekretów klienta, VM ani płatności. Dowody CI zawierają wyłącznie dane syntetyczne i pozostają przez siedem dni. Akcje są przypięte do SHA. Sam plik workflow nie stanowi dowodu udanego uruchomienia; rzeczywisty wynik zapisujemy w raporcie realizacji.

Weryfikacja zamrożonego V13 z 9.10.2026: `node /app/node_modules/typescript/bin/tsc --noEmit --incremental false` zakończył się kodem 0 w 15,024 s, a oficjalny `node scripts/qa/run-tests.mjs` zakończył się kodem 0 w 234,893 s: 351/351 PASS w 41 plikach, zero błędów, anulowań i pominięć. Przebieg korzystał z Node 22.23.3, `NODE_ENV=production` i własnego wykonywalnego `TMPDIR`, bez retry i narzuconego timeoutu. Wszystkie 319 hashów źródeł pozostały zgodne z manifestem V13, w tym typy Payload; archiwum wyklucza `tsconfig.tsbuildinfo`. Pełne logi wskazuje prywatny `native-v13-summary.json`.

Cztery nowe testy użyły rzeczywistego `validateCatalog` i formattera błędów Payload: komunikat konfliktu magazynu pozostaje publiczny także przy pustej nazwie błędu, a zatwierdzona korekta operacyjna nadal zmienia stan. To sprawdzenie zachowania formattera, bez przypisywania utraty nazwy konkretnej przyczynie kompilacji. Test rezerwacji wywołał rzeczywiste zgłoszenie, odrzucił stary licznik miejsc kodem 403, potwierdził brak zmiany tytułu i rezerwacji oraz udaną edycję samego tytułu.
